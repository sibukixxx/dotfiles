# /address - レビュー対応

レビュー結果を確認し、妥当性を判断したうえで必要な修正だけを行う。
レビュアー（人間・AI どちらでも）の指摘がすべて正しいとは限らないので、各コメントを批判的に評価する。

## 使い方

```
/address              # 直前の会話に含まれるレビュー内容を対象にする
/address 123          # PR #123 のレビューコメントを gh api で取得
/address <PR URL>     # URL から PR 番号を抽出して取得
/address review.md    # ファイルに書かれたレビュー内容を読む
```

### 引数の解釈

- **無引数**: 直前の会話にあるレビュー内容（`/review`、`/code-review`、`/ponytail` 等の出力を含む）
- **数値のみ**: PR 番号
- **github.com を含む URL**: PR URL。番号を抽出する
- **それ以外**: レビュー内容が書かれたファイルパス

## 手順

1. 引数を解釈し、レビューコメントを集める
   - PR 番号が分かる場合は 2 系統とも取得する（`{owner}` `{repo}` は `gh api` が自動展開する）
     - `gh api repos/{owner}/{repo}/pulls/<番号>/reviews` — レビュー本文
     - `gh api repos/{owner}/{repo}/pulls/<番号>/comments` — 行単位のインラインコメント
2. 各コメントの妥当性を評価する
   - 技術的に正しいか（実際のコードを読んで確認する。推測で判断しない）
   - プロジェクトの方針・CLAUDE.md・既存の設計判断と合致するか
   - 実装上のトレードオフとして受け入れ済みのものではないか
3. 妥当と判断した指摘だけ修正する。修正はテストが通ることを確認してから完了とする
4. 最後にサマリーを出力する

## サマリーの形式

```markdown
## レビュー対応サマリー

### 対応した指摘
| 指摘 | 修正内容 |
|------|----------|
| 指摘1 | 修正の概要 |

### 対応しなかった指摘
| 指摘 | 理由 |
|------|------|
| 指摘X | 対応不要と判断した根拠（レビュアーが納得できる形で） |
```

このサマリーは `/reply-review` が返信文を作る入力になるので、省略せず出力する。

## 注意

- 指摘を鵜呑みにしない。対応しない場合は理由を明記する
- 修正で新たな問題が入っていないか、関連テストを実行して確認する
- 修正はコミットしない（コミットは `/commit-push` や `commit-pusher` に任せる）
